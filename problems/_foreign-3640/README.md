# 3640 的异题数据备份（数据缺陷第 24 类，T78）

## 为什么在这里

`new_ROJ/problems/3640/data/` 原本含 **两套互不相同**的数据：

| 序列 | 数量 | 首行形态 | 示例答案 |
|---|---|---|---|
| `classroom1..25.in/.ans` | 25 对 | `1 1 300 34973`（4 整数 + 多行浮点）| `0.00` |
| ★ `problem1..20.in/.ans` | 20 对 | `1 2` / `1 1`（**图的边**）| `0` |

★ 机械判据：`cmp classroom1.in problem1.in` ⇒ **不同**；`.ans` 也 **不同**。

## 判据（决定性）

原闸门结果 **恰好是 `PASS=25, FAIL=20`**：

```
= 「classroom 序列【全过】」+ 「problem 序列【全败】」
⇒ 这不是「算法在 20 个点上错了」，而是【数据分两套】的指纹
```

★ **判据模式**：当失败数**恰好等于某个文件序列的长度**时，
应怀疑「目录里有多个序列」，而不是「算法部分正确」。

## 处置

1. ★ **不做**「让 20 个异题点通过」的努力（那是 `T62`：不该反解）
2. 异题 40 个文件**移出** `data/`，备份到本目录
3. 移出后闸门 **PASS=25/25**（`main.cpp` 与 `main.py` 双通过）
   ⇒ 证实主解对**本題序列**完全正确

⇒ `T78` 更隐蔽：**一部分点会通过**，看起来像「算法不够好」。

## 为什么是数据缺陷

`139108` 不是最优值；**真最优 = 124850**（少 14258）。

### 三条互证

**（i）显式证书**（只凭 4 个矩形框，不含任何程序输出）：

```
x[7,389]y[426,496] = (389-7) × (496-426) = 382 × 70  = 26740
x[42,391]y[16,185] = (391-42) × (185-16) = 349 × 169 = 58981
x[94,374]y[296,359] = (374-94) × (359-296) = 280 × 63 = 17640
x[427,484]y[11,388] = (484-427) × (388-11) = 57 × 377 = 21489
                                        合计 = 【124850】
```
逐点验证：50 点全覆盖、每点恰在 1 个矩形内、每矩形恰为其点集的外接盒、
6 对矩形全部**严格**分离（最近一对间隔 35）。

**（ii）异源算法族**：候选矩形集合覆盖（177626 个候选）；
代价 `< 124850` 时**枚举为空** ⇒ 下确界。

**（iii）全叶子枚举**：全部合法值 = `124850, 128726, …, 138895, 139108, …`
⇒ `124850` 最小，`139108` 只是**第 18 个**。

### ★★★ 最有力旁证：两个点共用同一组数据，但 `.out` 自相矛盾

```
jxfg4.in 与 jxfg5.in 是【同一组 50 点】（逐字节同体，仅首行 `50 3` / `50 4`）
该点集最优：k=1 → 231345 · k=2 → 190942 · k=3 → 156041 · k=4 → 124850
⇒ jxfg4.out = 156041  ✅ 正确
⇒ jxfg5.out = 139108  ❌ 与之矛盾
```

★ 且 `139108` 恰等于「y 连续段切分」的值，**但**同一模型给 `jxfg6 = 2134 ≠ 2106`
⇒ **不存在任何模型能同时产出全部 7 个 `.out`** ⇒ `.out` 集合内部不自洽，
  `jxfg5.out` 是唯一坏点。

### 已排除的替代解释

坐标笔误（±1 / ±2 / 交换 / 替换全部试过）、丢点 / 前后缀 / 转置 / 逆序 / 排序
（全给 124850）、节点截断（139108 从未作为搜索改进值出现）、溢出（UBSan + `-ftrapv` 干净）。

## 其他数据特征（**未修改**，仅记录）

- `.in` 行尾**混用**：`jxfg0–4` 是 CRLF、`jxfg5/6` 是 LF
